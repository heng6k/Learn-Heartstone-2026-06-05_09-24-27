# v0.1-alpha 发布包计划

## 目标

做出一个可以发给 10-20 个种子用户试用的 Windows Alpha 包，用来验证这个训练器是否真的能帮助玩家复盘、构造局面、测试站位和发现机制问题。

本版本不承诺完整官方复刻，也不追求 UI 完美。发布重点是：能打开、能进入主流程、能稳定跑一次核心对局、能让用户知道如何反馈问题。

## 输入门槛

开始打包前必须满足：

1. 功能冻结已生效，不再新增英雄/伙伴机制、不重做大 UI。
2. 全量 EditMode 完成一次记录；如果 Unity/MCP 阻塞，必须写明阻塞原因并补跑。
3. 卡池版本控制关键路径通过：弹窗打开、改名、筛选、滚动加载、剔除、保存、进入对局生效。
4. `Docs/CardPoolVersionControlBugHuntReport.md` 和英雄/伙伴缺口文档已更新。
5. 已知问题里明确写出 Alpha 限制，尤其是英雄/伙伴代理实现、缺图、UI 粗糙和反馈复现能力不足。

## 包内容

发布包建议命名：

```text
BattlegroundsTrainer_v0.1.0_alpha_win.zip
```

压缩包内至少包含：

1. Windows 可执行文件和 Unity 运行依赖。
2. `README_使用说明.md`。
3. `KNOWN_ISSUES_已知问题.md`。
4. `CHANGELOG_更新记录.md`。
5. `FEEDBACK_反馈说明.md`。
6. `SCENARIOS_示例场景.md` 或示例场景文件夹。

## 打包前检查

### 自动测试

1. 跑全量 EditMode。
2. 跑卡池版本控制相关 UI 测试。
3. 跑卡池进入对局过滤测试。
4. 跑官方单人卡池一致性测试。
5. 如果改过战斗或数值，补跑 `StressTests` 和 `RobustnessEdgeTests`，但 30 分钟 soak 只在专门稳定性验证时运行。

### 手动冒烟

按这个顺序验证：

1. 启动游戏进入入口页。
2. 打开卡池版本控制弹窗。
3. 复制默认版本并重命名。
4. 在随从标签筛选等级/种族，滚动到底部继续加载。
5. 剔除一批随从并保存。
6. 切到法术标签，搜索、剔除并保存。
7. 进入训练器对局，确认选择的版本生效。
8. 执行刷新、购买、出售、下一回合。
9. 运行一次战斗。
10. 查看战斗日志和招募日志。

通过标准：没有启动崩溃、没有主流程卡死、卡池过滤不会生成已剔除卡牌、战斗能结束并产生可读日志。

## 文档任务

### README_使用说明

必须写清：

1. 当前是 Alpha。
2. 主要用途是复盘、模拟、站位测试、机制验证。
3. 当前不是完整新手教程，也不是官方完全一致模拟器。
4. 基础操作入口：进入训练器、编辑卡池版本、开始对局、运行战斗、查看日志。

### KNOWN_ISSUES_已知问题

至少包含：

1. 部分英雄/伙伴仍是代理实现或框架优先实现。
2. 部分复杂机制和官方行为不完全一致。
3. UI 仍偏工程化，小窗口下需要继续观察。
4. 部分卡牌图片可能缺失。
5. 批量剔除还没有撤销按钮。
6. 反馈导出能力还不完整，复杂问题需要用户附截图和操作描述。

### CHANGELOG_更新记录

v0.1.0-alpha 重点写：

1. Unity 训练器主流程。
2. 核心酒馆操作。
3. 战斗模拟和日志。
4. 英雄/伙伴效果第一批覆盖。
5. 卡池版本控制：命名、筛选、剔除、保存、滚动加载、排除双打卡。

### FEEDBACK_反馈说明

反馈格式建议：

```text
期望结果：

```

## 示例场景

1. 基础买卖刷新流程。
2. 三连与发现。
3. 嘲讽/圣盾/亡语站位。
4. 低攻高血长战斗。
5. 酒馆法术购买与使用。

## 风险与处理

| 风险 | 处理 |
| --- | --- |
| Unity 测试被已打开编辑器或 MCP 阻塞。 | 记录阻塞原因，关闭多余编辑器后补跑；不把旧结果当成本轮通过。 |
| 用户误解为正式版。 | README 和发布文案首屏明确 Alpha 定位。 |
| 英雄/伙伴机制被挑错。 | 已知问题列出代理实现，反馈按 P1/P3 分类处理。 |
| 卡池版本误操作。 | 发布前优先验证保存、放弃修改、批量剔除、滚动加载路径。 |
| 缺图影响理解。 | 缺图显示卡牌编号，并在资源审计文档继续汇总。 |

## 发布后 72 小时

1. 收集所有反馈并按 P0-P4 分类。
2. P0 启动/主流程问题立即修。
3. P1 战斗错误、数据丢失、卡池版本失效进入 hotfix 候选。
4. P2 UI 难用进入下一版小修。
5. P3 英雄/伙伴不精准进入缺口文档排序。
6. 第 72 小时汇总：成功打开人数、完成首场战斗人数、最常见 5 个卡点、最需要的下一功能。

## 完成定义

v0.1-alpha 发布包完成时应具备：

1. Windows zip 包可解压运行。
2. 包内文档齐全。
3. 全量测试或阻塞补跑记录齐全。
4. 手动冒烟清单有结果。
5. 已知问题不隐瞒关键限制。
6. 可以发给第一批种子用户。
