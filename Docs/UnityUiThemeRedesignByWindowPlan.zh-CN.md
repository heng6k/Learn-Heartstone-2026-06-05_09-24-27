# Learn Heartstone Unity UI 主题化重做：逐页面与逐窗口改善方案

## 1. 文档目的

本文定义 `Learn Heartstone` 当前 Unity UI 的完整主题化重做方案，覆盖主页面、开局配置、酒馆训练主界面、所有运行时弹窗、抽屉、追踪器、工具窗口，以及仍保留在项目中的 Legacy/Realistic 兼容页面。

本轮只形成设计与实施规格，不直接修改代码、Prefab、玩法规则或数据。

最终目标是：在所有现有功能、命令、筛选能力、数据展示和操作路径保持不变的前提下，将界面统一为更舒适、更清晰、更有完整游戏氛围的原创主题。

## 2. 不可改变的功能边界

主题化重做必须遵守以下约束：

- 不删除、合并或隐藏现有可用功能入口。
- 不改变 `MatchService`、命令、卡池、战斗、任务、饰品、畸变、时空酒馆等规则。
- 不改变按钮点击后的业务行为、参数或目标对象。
- 不改变已有筛选项、搜索能力、批量操作和卡牌库目标位置。
- 不改变模态窗口的阻塞关系、返回逻辑和确认语义。
- 不用视觉改造绕过服务层状态限制。
- 可以调整布局、尺寸、视觉层级、组件皮肤、焦点顺序和响应式排列，但必须保证所有操作仍然可达。
- 不复制《炉石传说》或其他游戏的受保护卡框、图标、背景、角色、美术纹样和完整界面布局。
- 新增素材必须为项目原创、明确授权素材或许可证兼容的开源素材。

## 4. 统一主题方向

### 4.1 主题名称

**星灯秘法酒馆（Star-Lantern Arcane Tavern）**

视觉关键词：深色胡桃木战术桌、旧羊皮纸、黄铜包边、铸铁结构、蜡封标签、蓝色秘法辉光、暖色星灯、局部宝石材质。

该方向延续项目现有“酒馆训练桌”的语义，但建立原创材料、纹样和组件体系，不复刻任何现有商业游戏的界面资产。

### 4.2 材质分工

| 材质 | 使用位置 | 视觉目的 |
|---|---|---|
| 深胡桃木 | 主背景、棋盘承载面 | 稳定、沉浸、降低视觉疲劳 |
| 羊皮纸 | 详情、说明、日志、筛选面板 | 提升长文本阅读舒适度 |
| 黄铜 | 主操作、标题分隔、资源强调 | 建立层级与奖励感 |
| 铸铁 | 工具、调试、危险操作 | 将开发工具与主游戏体验区分 |
| 蓝色秘法玻璃 | 选中、可操作、焦点、特殊机制 | 提供清晰的交互反馈 |
| 暗红蜡封 | 删除、退出、危险确认 | 建立稳定的危险语义 |

| `Gold` | `#E0B858` | 奖励、主强调 |

颜色不能作为唯一信息来源。危险、禁用、可选择、当前选中等状态必须同时使用边框、图标、明度、纹理或文字。

### 4.4 字体系统

- 中文标题：思源宋体或同类开源宋体，使用 SemiBold/Bold。
- 中文正文：思源黑体或同类高可读无衬线字体。
- 英文标题：与中文标题气质匹配的 Serif 字体。
- 数字与资源：使用清晰的等宽或高识别度数字字形，不使用过度装饰字体。
- 1080p 下普通正文建议不低于 18，次级文字不低于 16，关键资源和状态不低于 24。
- 动态背景上的文字统一增加深色描边、Underlay 或半透明承载底。

### 4.5 间距与尺寸

沿用现有 `4/8/12/18`，扩展为：

- `SpacingXs = 4`
- `SpacingSm = 8`
- `SpacingMd = 12`
- `SpacingLg = 18`
- `SpacingXl = 24`
- `Spacing2Xl = 32`

所有主要按钮在 1080p 参考分辨率下交互区域不低于 `48×48`，主要确认按钮建议高度 `52–56`。图标可以小于 48，但可点击区域不能缩小。

### 4.6 动效系统

- Hover：120ms，亮度和边框增强，缩放不超过 `1.03`。
- Pressed：80ms，缩放至 `0.97–0.98`。
- 普通弹窗：150–200ms 淡入并由 `0.96` 缩放至 `1.0`。
- Toast：180ms 淡入，停留时间按文本长度调整。
- 禁止让 UI 跟随战斗画面震动。
- 禁止大幅弹跳、旋转、长距离滑入和持续呼吸动画。
- 预留“减少动态效果”选项，开启后只保留透明度变化。

### 4.7 层级系统

建议建立固定层级，而不是由各窗口自行抢占显示顺序：

1. 基础页面与棋盘
2. 常驻 HUD、追踪器和操作栏
3. 抽屉、对手配置和回放面板
4. 阻塞式模态窗口
5. 模态内详情窗口
6. Tooltip、目标连线、拖拽幽灵
7. Toast 和全局错误提示

## 5. 响应式规则

继续使用现有 `UnityTavernLayoutContext`：

| 模式 | 条件 | 主题化重做规则 |
|---|---|---|
| Wide | 宽度 >= 1400 且高度 >= 800 | 右侧检查器可常驻；棋盘、商店和手牌完整展示 |
| Standard | 介于 Wide 与 Compact 之间 | 检查器默认折叠；工具和日志使用抽屉 |
| Compact | 宽度 < 1000 或高度 < 650 | 辅助区改底部抽屉；缩短对手区；操作栏保持可见；长列表必须滚动 |

所有静态文字与交互元素保持在屏幕 90% 安全区内。不得以继续整体缩小 UI 的方式解决短屏问题，应折叠次要内容、减少装饰密度或切换排列。

## 6. 路由级页面改善措施

### P01 主大厅 Main Hub

当前职责：语言切换、进入 Unity 酒馆训练器、展示四个预留模块。

改善措施：

- 使用一张完整的“酒馆入口桌”作为主视觉，主训练入口做成中央大型黄铜铭牌，而不是普通矩形卡片。
- `Learn Heartstone` 标题使用星灯与木刻招牌风格，副标题降低装饰度并提高可读性。
- 中文/English 切换改为右上角小型黄铜拨片，当前语言拥有明确勾选和焦点环。
- 四个未开放模块放入“封存卷宗”区域，统一使用低对比羊皮纸封条和“预留”状态，不与主入口竞争。
- Compact 模式只显示标题、主入口、语言按钮和一个“查看预留模块”折叠入口。
- 主入口 Hover 时使用局部暖光和轻微浮起，不使用大幅缩放。

功能保持：语言切换、主入口回调、四个禁用模块和现有中英文文本全部保留。

### P02 Unity 酒馆开局配置页

当前职责：选择英雄、种族、卡池版本和高级机制，然后开始训练。

改善措施：

- 将页面组织为“开局卷宗”：顶部为当前英雄和版本摘要，中部为种族徽章板，底部为开始与高级设置。
- 当前英雄、卡池版本和高级机制状态使用三张摘要卡，每张都具有“当前值、状态、编辑”三层信息。
- 种族按钮改为徽章式切换卡；选中使用蓝色秘法环和勾选纹章，未选中保持木质底，不只改变颜色。
- “全部种族”“使用当前选择”等快捷配置放入独立的快捷栏，避免与开始按钮混淆。
- 开始训练按钮使用唯一的主操作金色样式；返回主大厅保持次级样式。
- 复杂编辑功能保持为模态窗口，不在主页面同时展开大量列表。

功能保持：所有种族选择、英雄选择、版本摘要、快速配置、高级机制入口和开始训练参数保持不变。

### P03 Unity 酒馆训练主界面

当前职责：完整酒馆操作、棋盘编辑、战斗测试、回放、建议、日志和调试工具。

改善措施：

- 将商店、己方棋盘和手牌明确设为视觉主舞台；辅助面板不得长期挤压三者。
- 背景从纯色面板改为分层战术桌：商店位于暖光区，己方棋盘位于中性木纹区，对手区域使用冷暗色区。
- 将状态、资源、英雄、效果、任务、饰品和操作按重要性分层，避免全部使用同等亮度。
- 所有区域标题使用统一黄铜铭牌，并显示简短容量信息，例如 `商店 5/5`、`己方 4/7`、`手牌 8/10`。
- 卡牌始终以卡图和战斗决策信息为主，完整文本进入详情窗口或检查器。
- Wide/Standard/Compact 三种模式必须分别设计构图，不允许只按比例缩小。

功能保持：当前所有命令、拖拽、选中、回放、工具、卡牌库和高级机制入口不变。

### P04 Realistic Trainer

当前职责：较早的主题化训练页面，包含主桌面与多标签抽屉。

改善措施：

- 作为兼容页面使用与主 Unity Trainer 相同的颜色、字体、按钮和卡牌状态令牌。
- 保留其“单桌面+右侧抽屉”结构，但移除与新主题冲突的独立色值和重复装饰。
- 页面顶端增加“兼容视图”小型标记，避免用户误以为它是当前主实现。
- 抽屉、发现窗口和 Toast 直接复用新主题组件视觉，不再维护另一套皮肤。

功能保持：所有 Realistic 页面操作、抽屉、对手编辑、战斗、回放和调试能力保持不变。

### P05 Legacy Trainer

当前职责：兼容/工具型密集工作台。

改善措施：

- 明确定位为“经典工作台”，使用较克制的羊皮纸与铸铁工具风格。
- 顶部显示兼容标记和返回新界面的入口说明，但不移除任何功能。
- 将密集面板按工作区分组，统一标题、滚动和选中状态。
- 保留其高信息密度，不强行改成卡牌游戏主界面；重点提升文字、表格、输入框和按钮的一致性。

功能保持：所有旧训练器工具和编辑能力完整保留。

## 7. 开局配置页逐窗口改善措施

### S01 英雄选择窗口

- 顶部固定显示标题、搜索、分类和当前选择摘要。
- 英雄使用纵向肖像卡：头像、英雄名、生命/护甲、技能类型和实现状态分层展示。
- “当前”“可替换”“代理”“未完成”“禁用”等状态使用角标形状加文字，不只使用颜色。
- 当前英雄保持蓝金双层描边；不可选英雄降低饱和度并显示明确原因。
- 右侧或底部预览区显示完整英雄技能和确认影响。
- “选择此英雄”“确认更换”“关闭”使用稳定的确认/取消位置。

### S02 卡池版本编辑窗口

- 使用“版本书库”布局：左侧版本列表与命名操作，右侧卡牌搜索、筛选和内容列表。
- Minions、Tavern Spells、Timewarped Tavern 使用书签式 Tab，并保持当前 Tab 明确可见。
- 搜索、等级、种族、状态筛选组成一条固定筛选栏；已启用筛选显示可移除的蜡封 Chip。
- 卡牌行包含缩略图、名称、类型、状态和开关；整行可聚焦，开关区域不小于 48px。
- 新建、复制、保存、删除等操作按普通、主要、危险语义区分。
- 长列表必须滚动，加载更多状态使用底部明确提示，不让滚动位置突然跳动。

### S03 卡池版本切换确认窗口

- 使用小型蜡封确认框，不重复展示整个版本编辑器。
- 清楚说明未保存更改、将切换到的版本和可能丢失的内容。
- 主按钮使用“保存并切换”或当前已有确认语义；危险放弃使用暗红色。
- 默认焦点放在最安全操作上，Esc/B 返回取消。

### S04 高级机制配置窗口

- 将任务/奖励、饰品、畸变和时空酒馆做成四张机制卷宗卡。
- 每张卡显示启用状态、当前池摘要、快速启用和编辑入口。
- `Proxy-safe`、调试池、隐藏效果池、禁用池、自由选择等开发选项放入铸铁“高级/调试”分区。
- 普通玩家功能与 DebugOnly 内容通过材质和标题明确分层。
- 底部固定“返回配置”和“开始训练/继续”操作，避免滚动到底才能确认。

### S05 高级机制卡池编辑窗口

- Quest/Reward、Trinkets、Anomalies 使用固定顶部 Tab。
- 搜索、类型筛选、实现状态筛选和批量操作按两行布局；Compact 模式改为可折叠筛选抽屉。
- 每一行显示图像、名称、类型、实现状态、可提供状态和开关。
- “已实现”“可提供”“调试”“禁用”同时使用图标、文字和边框纹理。
- 批量全选/清空必须与单项开关视觉区分，并在执行后给出 Toast。

## 8. Unity 酒馆主界面基础区域改善措施

### T01 顶部状态栏与英雄效果架

- 回合、金币、酒馆等级、生命、护甲等使用独立状态徽章，并按资源、生命、进度分组。
- 英雄头像与英雄技能形成一个整体徽章，点击区域和当前可用状态清晰可见。
- 英雄效果架改为横向卷轴/徽章架；常驻显示名称和状态，详细描述进入 Tooltip。
- 效果过多时折叠为 `+N`，避免挤压核心资源。
- 返回、设置、语言等全局操作置于固定角落并保持安全边距。

### T02 对手摘要入口与对手配置窗口

- 常驻入口只显示对手头像、生命/护甲、棋盘数量和关键机制 Chip。
- 点击后打开独立对手档案窗口，不在主界面展开大量编辑字段。
- 对手配置窗口分为英雄技能、任务奖励、饰品、棋盘、手牌/战斗法术等分区。
- 目标选择器使用清晰的己方/敌方图形标识，不只依赖红绿颜色。
- 对手机制库入口统一使用“浏览/更换”按钮，当前配置始终在入口旁可见。

### T03 商店区

- 使用最暖的桌面光照和黄铜标题，明确它是购买决策中心。
- 商店槽位使用木制卡座；冻结时出现霜纹、雪花图标和文字状态。
- 可购买卡牌显示费用宝石、轻微金色边缘和清晰 Hover；金币不足时显示暗化加费用不足图标。
- 刷新、冻结、升级靠近商店，但不覆盖卡牌。
- 满商店时卡牌保持等距；Compact 模式允许横向滚动或缩小装饰，不缩小关键文字。

### T04 对手棋盘与对手手牌区

- 对手棋盘使用冷色木纹和暗红/铁质边框，与己方明确区分。
- 对手手牌若可见，使用背面/摘要表达，不与己方手牌采用同样视觉权重。
- 目标可选时使用红色三角标记、描边和连线；不可选目标降低亮度并显示禁止符号。
- Compact 模式默认缩短对手区高度，但保留攻击、生命、嘲讽、圣盾等关键状态。

### T05 己方棋盘区

- 使用中性木纹和蓝金边框，七个槽位在所有分辨率下保持可区分。
- 随从卡优先显示攻击、生命、酒馆等级和最多三个关键状态。
- 重排落点显示插入位置和序号，不只高亮整个棋盘。
- 可编辑、可出售、可作为目标等状态使用不同角标，不让一圈彩色描边承担全部含义。
- 大数值使用缩写或紧凑排版，但 Hover/详情必须显示完整数字。

### T06 手牌区

- 手牌采用轻微扇形或分层卡座，但不能影响精确点击和拖拽。
- 可打出、可使用、等待目标、不可使用分别使用蓝色秘法边、目标图标、禁用纹理。
- 手牌达到上限时显示 `10/10` 警告和满手图标，不使用持续闪烁。
- 拖起卡牌后只突出合法落点，非法区域降低对比度。

### T07 酒馆操作栏与快捷操作栏

- 按行为分组：经济操作、回合主操作、战斗测试、回放/工具。
- 刷新/冻结/升级使用经济色；结束回合使用唯一主操作金色；开战使用战斗红；回放/工具使用功能蓝。
- 每个按钮拥有 Normal、Hover、Pressed、Selected、Disabled、Cooldown/Locked 状态。
- 禁用按钮必须显示原因 Tooltip，例如金币不足、无回放、当前状态不可执行。
- Compact 模式优先保留图标加短标签，不能只留下难以理解的图标。

### T08 右侧检查器抽屉

- 保留操作、详情、建议、日志四个 Tab，统一使用书签式标签。
- 当前 Tab 采用蓝色秘法高亮、加粗标题和顶部指示条。
- Wide 模式可常驻；Standard/Compact 默认折叠，并记住最后打开的 Tab。
- 抽屉宽度不再固定挤压棋盘；Compact 模式改为底部抽屉。
- 操作 Tab 保持按钮网格；详情 Tab 使用羊皮纸；建议和日志使用可扫描条目行。

#### T08-A 操作 Tab

- 将与当前选中卡牌有关的操作集中展示。
- 主次按钮按风险排序，危险操作保持固定位置。
- 无选中对象时显示简洁空状态，不显示大量禁用按钮。

#### T08-B 详情 Tab

- 顶部显示选中卡缩略图和名称，正文显示规则文本、来源、ID 和状态。
- 长文本使用羊皮纸高对比阅读区，关键词可点击/悬停解释。

#### T08-C 建议 Tab

- 每条建议使用左侧语义色标、标题和一句理由。
- 推荐、警告、风险使用图标加文字，不只使用颜色。

#### T08-D 日志 Tab

- 招募与战斗日志分组显示，时间/回合信息弱化，结果与关键变化强调。
- 支持滚动到底部，同时保留“回到最新”按钮。

### T09 任务追踪器

- 主任务和奖励任务使用两张紧凑卷轴卡。
- 进度同时使用数值和进度条；完成状态使用印章图标。
- 任务奖励库入口放在对应任务行内，不跨区域跳转。
- 无任务时折叠为小型未启用提示。

### T10 饰品追踪器

- Lesser 与 Greater 饰品使用两个固定槽位，视觉材质和等级明显不同。
- 显示图标、名称和核心效果摘要；完整文本进入 Tooltip/详情。
- 更换入口靠近对应槽位，避免用户不清楚修改目标。

### T11 高级选择状态面板

- 只显示仍待处理的选择请求，不长期占据主界面。
- 每一项显示类型、来源、剩余步骤和继续按钮。
- 阻塞主流程的选择使用明显边框和“需要处理”文字，但不持续闪烁。

## 9. Unity 酒馆逐窗口改善措施

### T12 返回主大厅确认窗口

- 使用小型蜡封确认框，说明当前训练进度是否会丢失。
- “继续训练”放在安全主位置，“返回大厅”使用危险/次级样式。
- 默认焦点为继续训练，Esc/B 等价于取消。

### T13 卡牌详情窗口

- 左侧显示大卡图，右侧羊皮纸显示名称、类型、等级/费用、规则文本、关键词和来源。
- 关键词以可聚焦 Chip 展示，Hover 延迟约 300ms 后显示解释。
- 卡牌 ID 和调试字段放在折叠的“技术信息”区。
- 没有选中卡牌时显示清晰空状态。
- 关闭按钮始终固定在右上安全区，同时支持 Esc/B。

### T14 战斗回放窗口

- 顶部：战斗结果、伤害、种子、当前帧和关闭按钮。
- 中部：我方/对手棋盘使用蓝/红双栏，当前攻击者与目标使用连线和标记。
- 底部：上帧、播放/暂停、下帧、速度和时间线。
- 事件列表按攻击、召唤、死亡、亡语、奖励等分类，并使用图标加文字。
- 时间线默认可折叠；Compact 模式优先保留棋盘与播放控制。
- 回放动画只表现事件结果，不引入改变帧语义的装饰性延迟。

### T15 训练工具窗口

- 使用铸铁工具箱主题，与普通游戏窗口明确区分。
- 顶部使用工具分类 Tab：常用、卡牌获取、高级机制、状态修改、场景/调试。
- 所有长列表可滚动，筛选栏固定，当前筛选以可移除 Chip 展示。
- 危险工具使用暗红警示条和确认步骤；普通测试操作不滥用红色。
- 调试解释和覆盖率信息使用表格/状态徽章，不堆成长段文本。

### T16 对局内英雄选择窗口

- 与 S01 共用英雄卡和搜索视觉组件。
- 增加当前对局状态提示，明确更换后会刷新哪些英雄属性。
- 当前英雄、不可选英雄、代理英雄和未实现英雄的视觉语义保持一致。

### T17 通用卡牌库窗口

- 左侧为等级/英雄信息筛选，中部为搜索和卡牌网格，右侧为类型/种族/目的地筛选。
- 顶部持续显示本次添加目的地：玩家手牌、对手手牌、对手棋盘或对手战斗法术。
- 卡牌网格以图像为主，名称、等级/费用、类型和加入按钮为辅。
- 加入按钮与卡牌详情按钮分离，避免误操作。
- 搜索结果数量和空状态始终可见。

### T18 卡牌库详情窗口

- 作为 T17 上层的小型详情模态，不关闭底层筛选状态。
- 展示完整卡图、规则、来源、ID 和当前加入目标。
- 主操作明确写出“加入玩家手牌”等具体动词和目的地。

### T19 高级卡牌库窗口

- Quest Reward、Lesser Trinket、Greater Trinket 使用统一机制库模板。
- 卡片显示类型、实现状态、可用条件和目标槽位。
- 当前任务索引或饰品槽位固定显示在标题旁。
- 不可用条目必须解释原因。

### T20 对手机制库窗口

- Hero Power、Quest Reward、Lesser Trinket、Greater Trinket 使用相同浏览器框架。
- 标题明确显示“正在配置对手”，避免与玩家卡牌库混淆。
- 当前对手配置使用勾选角标和“当前”文字。

### T21 机制卡详情窗口

- 显示机制图像、名称、完整文本、实现备注、来源 ID 和当前目标。
- 代理/调试/未完成状态使用独立技术信息区。
- 更换/选择按钮明确说明会影响玩家还是对手。

### T22 随从编辑窗口

- 顶部显示被编辑随从缩略图、名称和所属阵营。
- 攻击/生命输入使用数字步进器或清晰输入框，并即时验证非法值。
- 关键词使用带图标的多选 Chip；清空关键词是危险次级操作。
- “套用己方”“套用敌方”明确展示目标阵营。
- 保存为主按钮，取消固定在旁边；错误信息显示在输入区附近。

### T23 发现选择窗口

- 使用三张或实际数量的候选卡牌置于中央聚光区。
- 标题显示发现来源和选择提示。
- Hover 时显示详情，点击后先明确选中，再按现有交互立即确认或执行。
- 非候选区域暗化并阻止穿透点击。
- 控制器焦点在候选之间按逻辑顺序移动。

### T24 高级机制选择窗口

- 根据任务、奖励、饰品、畸变等类型更换标题纹章，但保持同一窗口骨架。
- Quest + Reward 成对选择时并排展示来源和奖励，关系清晰可见。
- 每个候选显示图片、名称、摘要、实现状态和选择按钮。
- 若允许进入玩家定向选择，入口使用“浏览全部可选项”而不是普通候选样式。

### T25 玩家定向选择窗口

- 顶部固定搜索和筛选；筛选项包含可选状态、费用、槽位和标签。
- 当前选择类型和目标位置使用明显上下文标题。
- 列表行显示缩略图、名称、类别、费用/槽位和可选原因。
- 无效项显示明确原因；不能只将按钮灰掉。
- 返回高级机制选择时保留原筛选状态。

### T26 时空酒馆窗口

- 保持独立五槽模态，不复用普通商店容量和布局。
- 使用蓝紫秘法裂隙、古铜时钟和时空资源宝石，形成与普通酒馆明显不同的短时体验。
- 顶部显示 Minor/Major、Chronum 数量和退出按钮。
- 五张卡按 Chronum 费用分组，已购买槽位保留清晰占位状态。
- 不可购买时同时显示费用不足/不可用文字和图标。
- 底层普通酒馆降暗并完全阻止交互；焦点必须被限制在时空酒馆内。
- 动效以淡入、时间刻度扫光和轻微粒子为主，不使用旋转屏幕或大幅扭曲。

### T27 错误提示与成功反馈 Toast

- 错误 Toast 使用暗红蜡封和警告图标；成功反馈使用绿色/金色印章。
- 同一时间最多显示 2–3 条，重复消息合并计数。
- 文本长度决定停留时间，重要错误允许手动关闭。
- Toast 不遮挡金币、结束回合、目标选择和模态确认按钮。

### T28 关键词与效果 Tooltip

- 延迟约 300ms 显示，避免鼠标经过时闪烁。
- 使用紧凑羊皮纸卡，标题、图标、简短说明和来源分层。
- 自动选择不会越界的位置，并与屏幕边缘保持安全距离。
- Tooltip 不接管点击，也不阻挡当前主要操作。

### T29 拖拽、落点与目标选择浮层

- 拖拽幽灵保持卡牌核心信息，但降低不必要文本和装饰。
- 合法落点使用蓝/金边框、图标和短动词；非法落点使用暗化与禁止标记。
- 棋盘重排显示具体插入线；出售区显示金币结果；手牌落点显示“加入手牌/使用”。
- 目标选择使用连线、目标环和目标类型文字，支持双目标步骤提示。
- 取消目标按钮保持固定位置，不随目标对象移动。

## 11. 卡牌框系统重做

### 11.1 共享结构

所有卡牌继续由同一数据和交互组件驱动，但视觉按使用位置切换密度：

| 模式 | 必须显示 | 可移至详情 |
|---|---|---|
| Shop | 图像、名称、等级/费用、购买状态 | 完整规则、来源、调试字段 |
| Board | 攻击、生命、等级、关键状态 | 完整规则文本 |
| Hand | 名称、费用/类型、可用状态 | 来源和长规则文本 |
| Discover/Choice | 图像、名称、核心摘要、选择状态 | 技术信息 |
| Replay | 攻击、生命、状态、事件高亮 | 非当前帧无关信息 |

### 11.2 卡框材质

- 普通随从：木质主体和金属角件。
- 金色随从：更精细的黄铜雕花，但不增加影响阅读的持续动画。
- 酒馆法术：羊皮纸与蓝色法术封边。
- 英雄/英雄技能：石雕或徽章式外框。
- 任务/奖励：卷轴与印章。
- 饰品：宝石或护符槽。
- 时空卡：蓝紫秘法金属与时钟刻度。

### 11.3 状态矩阵

每张可交互卡必须支持：Normal、Hover、Focused、Selected、Pressed、Disabled、Affordable/Unaffordable、Valid Target、Invalid Target、Dragging、Drop Accepted、Drop Rejected、Purchased/Consumed。

## 12. 按钮、输入和导航规范

- 主操作、次操作、经济、战斗、功能、危险六种角色继续对应现有按钮职责。
- 每个模态窗口只能有一个最强主操作。
- 确认与取消位置保持一致；返回/关闭不能在不同窗口交换位置。
- 所有交互元素支持键盘和手柄焦点，焦点标记不能只改变颜色。
- 模态打开时焦点进入模态，关闭后返回原入口。
- 长列表支持方向键、滚轮和 Page Up/Page Down；Tab/LB/RB 用于主要分类切换。
- 输入提示应由当前绑定动态生成，避免硬编码设备按键名称。

## 15. 验收标准

### 15.1 功能完整性

- 所有改造前可用按钮、Tab、筛选、列表、输入框和弹窗仍可使用。
- 所有命令参数和业务结果与改造前一致。
- 模态阻塞、关闭、取消和返回逻辑一致。
- 卡牌拖拽、目标选择、Discover、PendingChoice 和时空酒馆流程无回归。

### 15.2 视觉完整性

- 所有页面使用同一主题令牌，不再出现独立随意色值。
- 主操作、危险、战斗、经济、工具和禁用状态无需阅读说明即可区分。
- 商店、己方棋盘、对手棋盘和手牌具有明确材质与阵营差异。
- 每个窗口有清晰标题、内容区和操作区。

### 15.3 可读性与适配

- 在 `1920×1080`、`1366×768`、`1280×720`、`1000×600`、`994×384` 下无关键重叠或越界。
- 关键文字不低于可读尺寸，动态背景文字具备描边、阴影或承载底。
- 关键按钮实际交互区域不低于 48px 参考尺寸。
- 长列表可滚动，Compact 模式不会通过整体缩小导致不可读。

### 15.4 输入与可访问性

- 全流程可仅使用键盘或手柄完成。
- 焦点始终可见，模态不会产生焦点死路。
- 颜色信息均有图标、形状或文字辅助。
- UI 不跟随战斗震动，并支持减少动态效果。
