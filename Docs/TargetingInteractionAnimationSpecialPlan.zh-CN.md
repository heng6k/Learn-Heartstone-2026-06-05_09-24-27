# 指向交互与专门动画专项设计方案

> 文档状态：设计基线（第一版）  
> 编写日期：2026-07-14  
> 适用项目：`Learn Heartstone` Unity 酒馆战棋模拟/训练项目  
> 文档性质：玩法对齐 + UI/动画专项 + 后续实现计划  
> 当前阶段：核心目标契约、非法目标反馈、酒馆目标、双目标与显式指向随从已进入生产实现

## 实施状态（2026-07-14）

本专项的第一轮生产实现已经完成，当前代码已具备：

- 结构化目标评估与失败原因；
- 指向法术候选和确认前复用 `MatchService` 的同一套目标校验；
- `Source / Candidate / InvalidTarget / ConfirmedTarget` 视觉状态与专门脉冲反馈；
- 非法释放保持指向会话，可重新选择或取消；
- 只指向酒馆的英雄技能目标域限制；
- 沃金“灵魂互换”的双目标 `1/2 → 2/2` 流程、去重和跨己方战场/酒馆目标；
- 废铁残械、变装盗墓贼等显式指向随从效果的候选过滤与服务端强校验；
- 现有鼠标点击/拖拽取消路径和装饰层 `raycastTarget = false` 约束；
- 对应 UI、服务、英雄效果和验收回归测试。

后续新增指向卡牌时，应继续把卡牌加入统一目标规则，而不是在单个按钮回调中增加例外。

## 1. 为什么要单独建立指向专项

指向不是“拖一条线到某张卡”这么简单。它同时涉及：

1. 来源是什么：英雄技能、酒馆法术、普通法术、随从战吼、Spellcraft、磁力/选择型效果，还是回放中的自动事件。
2. 目标在哪里：己方战场、敌方战场、酒馆、手牌、英雄、多个区域的组合。
3. 目标是否合法：卡牌规则、当前回合、阶段、空位、目标类型、数量、是否已经被选过。
4. 玩家当前处于什么状态：尚未激活、正在选目标、悬停预览、已确认、结算中、取消、失败恢复。
5. 动画要告诉玩家什么：哪里能点、哪里不能点、为什么不能点、操作是否成功、是否还需要第二个目标。

如果没有统一契约，各个系统就会按自己的方式判断：

- 拖拽控制器按“来源 + drop target”猜目标；
- 领域服务按 `TargetZone`、索引和实例 ID 二次解析；
- 卡牌组件按 `Source/Candidate/ConfirmedTarget` 自己画框；
- 战斗回放又按 `ActorId/TargetId` 另画一套关系。

短期可以工作，长期会出现“UI 允许但服务拒绝”“服务允许但 UI 没有候选提示”“第二目标选完第一目标消失”“取消后残留红框/箭头”等问题。本专项的核心不是增加更多特效，而是让这些层共享同一个 Targeting Contract。

## 2. 目标、非目标与成功标准

### 2.1 目标

- 覆盖当前项目所有玩家主动指向：英雄技能、酒馆法术、普通法术、指向型随从效果、Spellcraft、双目标/多目标效果。
- 覆盖酒馆阶段的己方战场、敌方战场、酒馆随从、手牌等目标域。
- 复用已有 `GameCommand` 的目标索引、目标区域和实例 ID，不重复造一套不兼容的命令载荷。
- 把合法性、候选集合、目标顺序、取消规则和动画状态统一成可测试契约。
- 在鼠标、键盘/手柄、触摸三种输入下得到同一套状态语义。
- 把动画限制在短、清晰、可降级的反馈：默认不超过 300ms，提供减少动态效果模式。
- 让后续新增卡牌只需要声明目标规则，不需要在每张卡里重写高亮、连线和取消逻辑。

### 2.2 非目标

- 本文不重新定义法术、英雄技能或随从效果的结算规则。
- 本文不把购买、出售、移动、放置位置、召唤槽位选择误标成“指向目标”。
- 本文不要求一次性补齐所有历史卡牌效果；先建立通用能力，再按优先级迁移。
- 本文不把战斗自动攻击、随机目标、全体目标强行变成玩家指向；它们使用回放/结果可读性层。
- 本文不覆盖普通酒馆刷新、冻结、升级、购买确认等非目标交互。

### 2.3 成功标准

任意显式目标操作都应满足：

1. 玩家在 1 秒内能辨认“谁在作用于谁”。
2. 合法目标、非法目标、当前悬停目标、已确认目标的视觉语义稳定且不只依赖颜色。
3. 取消、目标失效、阶段切换、来源卡离场后，不残留框、箭头、标签、幽灵卡或 Raycast 阻塞。
4. 双目标/多目标操作明确显示选择进度，并保持已选目标可见。
5. UI 层和服务层对同一张卡给出一致的合法性结论。
6. 1920×1080、1280×720、994×384 以及 UI 缩放场景下不遮挡核心酒馆操作区。

## 3. 结合实际酒馆战棋的玩法基线

### 3.1 已核对的事实

Blizzard 28.2 官方补丁说明确认了酒馆法术的基础流程：酒馆法术在酒馆中购买，购买后进入手牌，之后由玩家在合适时机使用；它们有独立费用和法术卡框，并且每次刷新会额外提供酒馆法术槽位。[Blizzard 28.2 Patch Notes](https://hearthstone.blizzard.com/en-us/news/24008697/28-2-patch-notes)

这带来一个必须分开的流程：

```text
酒馆购买（非指向）
        ↓
酒馆法术进入手牌
        ↓
手牌施放（可能是非指向，也可能进入指向）
        ↓
选择目标 / 确认 / 结算
```

官方补丁中的卡牌文字还展示了多种真实目标域：

- `Give a friendly minion...`：己方战场随从目标；
- `Choose a minion in the Tavern...`：酒馆随从目标；
- `Choose a minion...`：不能仅凭自然语言猜域，必须由卡牌规则给出；
- `Choose 2 minions...`：多目标、目标顺序和目标去重都需要明确；
- 一些随从战吼/Spellcraft 在效果文本中选择目标，说明“随从”既可能是来源，也可能是随后产生的指向效果。

> 版本说明：28.2 是酒馆法术机制公开时的官方规则来源。卡牌文本和费用会随版本变化；本项目应把“目标域/数量/过滤器”作为数据契约，把具体数值和卡名作为可更新数据。HearthstoneJSON 最新英文卡库用于补充当前可检索的目标文本样本：[cards.json](https://api.hearthstonejson.com/v1/latest/enUS/cards.json)。

### 3.2 目标分类表

| 类别 | 真实玩法文本/实例 | 目标域 | 是否玩家主动指向 | UI 处理 |
|---|---|---|---|---|
| 己方战场单目标 | `Give a friendly minion...`、多数塑造法术 | `FriendlyBoard` | 是 | 来源金框、己方候选高亮、悬停目标红框 |
| 敌方战场单目标 | 对敌方随从造成伤害/施加负面效果的技能或法术 | `OpponentBoard` | 是 | 敌方候选可选，其余区域降亮 |
| 酒馆单目标 | `Choose a minion in the Tavern...` | `TavernShop` | 是 | 酒馆槽位高亮，不把战场随从误标成候选 |
| 跨区域任意随从 | `Choose a minion...` | 由卡牌声明的多个区域并集 | 是 | 目标域标签需显示，例如“战场/酒馆” |
| 手牌目标 | 给手牌随从加成、选择手牌中的卡 | `Hand` | 是 | 手牌卡片进入候选态，不能被场上装饰层遮挡 |
| 双目标/多目标 | `Choose 2 minions...`、先选来源再选目标 | 一个会话内多次选择 | 是 | `目标 1/2`、`目标 2/2`，保留已选目标 |
| 指向型随从战吼 | 上场后 `Battlecry: Choose a friendly...` | 通常 `FriendlyBoard` | 是 | 先完成上场，再开启独立选目标步骤 |
| Spellcraft 临时法术 | `Spellcraft: Give a minion...` | 通常 `FriendlyBoard` | 是 | 把临时法术视为手牌来源，不直接把生成者当目标 |
| 酒馆改造/复制 | 选择酒馆随从复制、改变或加入手牌 | `TavernShop` | 是 | 只高亮酒馆槽位，提示“酒馆目标” |
| 随机/全体/自动 | `random`、`all`、`each`、最低生命值等 | 规则自动解析 | 否 | 只显示结算结果，不出现“选择目标”状态 |
| 战斗攻击与触发 | 攻击者、受击者、死亡触发、召唤 | 战斗回放关系 | 否 | 使用来源/目标回放层，不阻塞玩家输入 |

### 3.3 不要混淆的四个动作

| 动作 | 是否指向 | 原因 |
|---|---|---|
| 从酒馆购买随从/法术 | 否 | 目标是购买槽位，属于购买操作，不是效果目标 |
| 把随从拖到战场某个位置 | 否（位置选择） | 这是放置索引，不是“效果作用于谁” |
| 把法术施放到指定随从 | 是 | 目标承载法术效果 |
| 自动攻击随机敌人 | 否（玩家视角） | 结算目标由战斗规则决定，玩家只看回放 |

## 4. 当前项目盘点

### 4.1 已有能力（优先复用）

当前项目已经具备一部分可复用基础：

- `GameCommand` 已有 `TargetIndex`、`SecondaryTargetIndex`、两个 `TargetZone` 和两个 `TargetInstanceId`，可以承载双目标和稳定实例引用。
- `TargetZone` 当前包含 `FriendlyBoard`、`TavernShop`、`OpponentBoard`、`Hand`，说明领域层已经开始区分区域。
- `UnityTavernCardComponent` 已有 `None`、`Source`、`Candidate`、`ConfirmedTarget`、`OpponentTarget` 状态。
- `UnityTavernTrainerController` 已有拖拽幽灵、候选卡反馈、短箭头连接器、取消按钮和确认目标短暂保留。
- `UnityTavernDragController` 已能把英雄技能指向玩家/对手战场，把带 `targeted_spell` 标签的手牌法术指向玩家战场，并为 Blood Gem 额外允许酒馆目标。
- `MatchService` 已在多个服务路径按区域、索引和实例 ID 解析目标，并已有双目标相关参数。
- `Docs/TargetingClarityDesign.zh-CN.md` 已定义金色来源框、红色目标框、候选/悬停/确认状态、短箭头、回放来源与目标的视觉基础。

### 4.2 当前缺口

1. **目标规则分散**：拖拽控制器、卡牌标签、服务校验各自判断，没有一个可查询的 Targeting Contract。
2. **目标域不完整**：没有玩家英雄、对手英雄、明确的酒馆法术槽位/区域类型；未来跨区域卡牌只能依赖 `Unspecified`。
3. **命令语义混用**：部分法术仍复用 `PlayMinion` 命令，UI 难以从命令名判断“正在施放法术并选择目标”。
4. **多目标流程未统一**：虽然载荷有 secondary target，但 UI 没有统一的“已选目标集合、顺序、去重、下一目标提示”。
5. **指向型随从效果覆盖不足**：随从战吼、Spellcraft、磁力/选择型效果容易被当成普通上场或自动触发。
6. **非法目标说明不足**：当前主要是降亮/红色，缺少“为什么不可选”的数据化原因。
7. **动画不可配置**：目标线、卡牌缩放、标签和确认保留时间散落在控制器中，无法按减少动态效果降级。
8. **回放与交互未分层**：已有 `ActorId/TargetId` 适合回放，但不应直接复用玩家输入态的取消、Raycast 和候选逻辑。

### 4.3 既有设计文档的定位

`Docs/TargetingClarityDesign.zh-CN.md` 继续作为视觉语言的基础文档；本专项补充它没有覆盖的部分：

- 目标数据契约；
- 目标域与过滤器；
- 会话状态机；
- 输入设备差异；
- 动画时间线与降级；
- 各类来源映射；
- Unity 代码落点；
- 单元、服务、UI、PlayMode 测试；
- 迁移顺序和回滚策略。

本专项不要求删除或重写旧文档，后续实现时应从旧文档复用来源/目标框、颜色、箭头和回放原则。

## 5. 统一 Targeting Contract

### 5.1 最小数据结构

建议新增一个轻量、只描述“当前指向会话”的数据契约，不把结算逻辑塞进 UI：

```text
TargetingRequest
├─ Source
│  ├─ sourceKind: HeroPower | TavernSpell | Spell | MinionEffect | Spellcraft | Replay
│  ├─ sourceCardId
│  ├─ sourceInstanceId（可空；英雄技能可用稳定虚拟 ID）
│  └─ sourceLabel
├─ TargetRule
│  ├─ allowedZones: FriendlyBoard / OpponentBoard / TavernShop / Hand / Hero...
│  ├─ requiredCount
│  ├─ allowDuplicate
│  ├─ selectionOrder: Any | Ordered
│  ├─ predicateId / filter parameters
│  └─ invalidReasonKey
├─ Selection
│  ├─ selectedTargets[]（实例 ID 优先，索引只作兼容）
│  ├─ currentStep
│  └─ hoveredTarget
├─ Input
│  ├─ activation: Click | Drag | ControllerConfirm | Touch
│  └─ cancelPolicy
└─ Presentation
   ├─ sourceStyle / targetStyle
   ├─ connectorMode
   ├─ promptKey
   └─ reducedMotionProfile
```

### 5.2 设计原则

- **实例 ID 优先**：卡牌移动、刷新或重排后，使用 `TargetInstanceId` 重新绑定；索引只用于旧命令兼容和 UI 槽位定位。
- **规则与表现分离**：`TargetRule` 决定谁可选；表现层只消费候选集合和状态，不自行猜测。
- **空集合可解释**：如果没有合法目标，来源按钮/卡牌显示禁用原因；不进入“空目标指向态”。
- **来源先验证**：费用、阶段、来源卡存在性和使用次数先验证，验证通过才创建会话。
- **目标再次验证**：确认时服务必须重新校验目标，不能信任 UI 在悬停时的结果。
- **会话可恢复**：候选目标失效时回到 `Armed` 或 `InvalidTarget`，而不是直接静默销毁。
- **不把动画当状态**：动画中断时仍以会话状态为准，必须可立即重绘。

### 5.3 目标过滤器分类

不要为每张卡写任意 Lambda；先建立有限、可测试的过滤器类型：

| 过滤器 | 说明 | 示例 |
|---|---|---|
| `IsFriendlyMinion` | 玩家战场存活/存在随从 | 己方增益法术 |
| `IsEnemyMinion` | 对手战场随从 | 敌方伤害技能 |
| `IsTavernMinion` | 当前酒馆槽位中的随从 | 复制/改造酒馆随从 |
| `HasTribe` | 目标必须拥有某类型 | 只对野兽/龙有效 |
| `HasKeyword` | 目标必须有关键字 | 只对嘲讽/磁力有效 |
| `NotSource` | 不允许选来源本身 | “另一个随从” |
| `HasSpace/CanReceive` | 目标能承载结果 | 磁力、附魔、临时效果 |
| `CardKind` | 目标卡种限制 | 只选随从/只选法术 |
| `Composite` | 多个过滤器 AND/OR | 己方 + 野兽 + 非金色 |

过滤器返回结构化结果：

```text
TargetValidationResult
├─ isValid
├─ reasonKey（例如 target_wrong_zone、target_wrong_tribe）
├─ reasonParameters
└─ priority（用于候选排序/手柄导航）
```

## 6. 指向状态机

### 6.1 状态定义

```text
Idle
  └─ ActivateSource → Armed
Armed
  ├─ HoverValid → Preview
  ├─ HoverInvalid → InvalidTarget
  ├─ Cancel → Cancelled → Idle
  └─ ConfirmValid → Resolving
Preview
  ├─ HoverAnother → Preview
  ├─ HoverInvalid → InvalidTarget
  ├─ Confirm → Resolving
  ├─ LeaveBoard/ReleaseOutside → Armed
  └─ Cancel → Cancelled → Idle
InvalidTarget
  ├─ HoverValid → Preview
  ├─ HoverAnotherInvalid → InvalidTarget
  ├─ Cancel → Cancelled → Idle
  └─ ReleaseInvalid → Armed（显示一次原因，不结算）
Resolving
  ├─ MoreTargetsRequired → Armed（step + 1）
  ├─ Success → Completed → Idle
  └─ Failure/SourceGone/PhaseChanged → Failed → Idle
```

### 6.2 状态与玩家可见反馈

| 状态 | 玩家看到什么 | 是否接受确认 | 动画目的 |
|---|---|---:|---|
| `Idle` | 普通卡面 | 否 | 没有额外指向层 |
| `Armed` | 来源金框、合法候选高亮、顶部提示 | 否/等待目标 | 告诉玩家“现在需要选谁” |
| `Preview` | 目标红框、来源到目标短箭头、目标名 | 是 | 告诉玩家“即将作用于谁” |
| `InvalidTarget` | 目标降亮、红色短促闪烁或原因标签 | 否 | 告诉玩家“这里不能选以及原因” |
| `Resolving` | 来源/目标锁定，其他交互冻结 | 否 | 表达已确认、正在结算 |
| `MoreTargetsRequired` | 已选目标保留，提示“请选择第 N 个目标” | 仅对下一目标 | 保持上下文，不让玩家以为已完成 |
| `Cancelled` | 清理全部指向层 | 否 | 立即恢复普通界面 |
| `Failed` | 一次性错误提示，清理残留 | 否 | 解释服务拒绝或对象消失 |

### 6.3 取消规则

所有输入设备都必须有等价取消：

| 输入 | 取消动作 |
|---|---|
| 鼠标 | 右键、Esc、拖回来源区、在空白区释放 |
| 键盘 | Esc；若有上一级选择则先返回上一步 |
| 手柄 | B/Circle；按住时松开不应误确认 |
| 触摸 | 拖回来源、滑出有效区域后松手、系统返回键 |
| 多目标 | 取消当前目标步骤；再次取消才退出整个会话（除非卡牌规则定义一次性取消） |

取消必须清理：`activeDrag`、drag ghost、候选高亮、目标连线、来源标记、确认目标短暂保留、顶部提示、Raycast 临时覆盖层。

## 7. 指向动画专项规范

### 7.1 视觉语法

延续现有文档的基础约定：

- 来源：金色实线框 + 来源标签；
- 合法候选：细金色虚线/低强度光晕；
- 悬停目标：红色实线框 + 目标标签；
- 已确认目标：红色实线框 + 角标/序号；
- 非法目标：降亮 + 非法图标/原因提示；
- 连线：短金色箭头，从来源边缘指向目标边缘；装饰图形 `raycastTarget = false`。

颜色不是唯一信息：必须同时提供边框形状、标签、图标或明暗差异。来源和目标也不能只靠红/绿区分。

### 7.2 默认动画时间线

所有时间以 `unscaledTime` 为基准，避免暂停/慢动作导致指向反馈卡住。

| 事件 | 默认时长 | 动画 | 备注 |
|---|---:|---|---|
| 进入 `Armed` | 120ms | 来源框淡入 + 候选轻微亮起 | 不做大幅位移 |
| 候选进入 | 100ms | 候选框/光晕淡入 | 可连续切换 |
| 悬停目标 | 90ms | 目标框加粗 + 目标名淡入 + 连线生成 | 目标名不遮挡攻血 |
| 非法目标 | 120ms | 低幅度红闪一次 + 原因标签 | 不抖屏、不震动整张卡 |
| 确认目标 | 140ms | 目标框锁定、角标出现、连线缩短 | 多目标保留序号 |
| 进入结算 | 180ms | 来源到目标一次性脉冲/粒子 | 只播放一遍，避免循环噪声 |
| 成功清理 | 160ms | 目标反馈淡出，结果反馈交给效果系统 | 不与伤害数字重复抢焦点 |
| 取消清理 | 100ms | 框/线快速淡出，幽灵卡缩回或消失 | 取消优先于装饰动画 |
| 错误恢复 | 180ms | 来源回到原位，错误提示 1.5 秒 | 仅保留一个主错误 |

默认总反馈不应超过 300ms；超过 500ms 的动画必须有明确理由和减少动态效果分支。

### 7.3 连线规则

- 只在 `Armed`、`Preview`、回放当前帧显示；普通待机不常驻。
- 连线从来源边缘到目标边缘，不穿过卡名、攻血、购买/出售区。
- 屏幕空间不足时先隐藏连线，保留来源框、目标框和标签。
- 同一来源的目标超过 3 个时，优先显示目标序号与事件文字，减少箭头数量。
- 连线节点和箭头永远不拦截鼠标/触摸；只有真正的目标卡/槽位接收 Raycast。
- 来源离屏或目标移动时，下一帧重算几何；禁止缓存过期的世界坐标。

### 7.4 减少动态效果模式

设置项：`设置 → 可访问性 → 减少指向动画`。

开启后：

- 取消卡片位移、弹性、旋转、屏幕震动；
- 连线改为静态细线或完全隐藏；
- 候选状态使用静态边框 + 图标；
- 非法反馈使用一次性颜色/图标变化，不循环闪烁；
- 确认只保留 80–120ms 的静态锁定；
- 不影响目标合法性、按钮可用性和文本提示。

## 8. 各类来源的专项交互

### 8.1 指向型英雄技能

#### 己方战场目标

1. 点击/拖拽英雄技能，先验证技能费用、冷却和当前阶段。
2. 来源技能按钮/拖拽幽灵显示金框和 `英雄技能` 标签。
3. 只把 `FriendlyBoard` 中通过过滤器的随从设为候选。
4. 悬停时显示目标红框、目标名和技能简述；确认后调用统一命令。
5. 结算失败时恢复技能可用状态，不留下已确认目标。

#### 酒馆目标

1. 来源仍然是英雄技能；候选区域改为 `TavernShop`。
2. 酒馆槽位显示 `酒馆目标` 标签，不能与购买高亮混用。
3. 如果效果会把目标加入手牌，确认动画应表现“酒馆 → 手牌”，而不是“战场命中”。
4. 刷新/冻结导致目标实例消失时，使用实例 ID 重新验证并进入失败恢复。

#### 双目标英雄技能

- 第一个目标确认后显示 `目标 1/2`；
- 已选目标保持红框并降低亮度，除非规则允许重复；
- 第二个目标只展示尚未满足数量/过滤器的候选；
- 第二个目标取消时，保留第一目标并回到 `Armed(step 2)`，再次取消才退出整个技能。

### 8.2 酒馆法术

酒馆法术分成两段：

```text
酒馆槽位 → 购买（非指向）
手牌法术 → 施放（按文本判断是否指向）
```

要求：

- 购买按钮、冻结按钮和指向目标框不能共用同一颜色语义；
- 从酒馆购买后进入手牌，法术卡必须保留 `CardKind.TavernSpell` 和目标标签；
- 手牌施放时若无合法目标，不进入空指向态，直接显示不可用原因；
- `Choose a minion in the Tavern` 只高亮酒馆槽位；
- `Give a friendly minion` 只高亮己方战场；
- 文本为 `Choose a minion` 时，由数据规则明确允许区域，禁止 UI 默认猜测；
- 法术结算完成后，目标反馈交给结果/效果动画，指向线及时清理。

### 8.3 普通法术

普通法术与酒馆法术共享 Targeting Contract，但来源标签必须显示 `法术`，不能误显示 `酒馆法术`。

- 普通法术进入手牌时即带目标规则；
- 非指向法术不能因为拥有 `Spell` 卡种而显示候选框；
- 指向法术可用点击来源后选择，也可按现有拖拽流程直接拖向目标；
- 服务层拒绝时，UI 展示服务返回的 `reasonKey`，不根据本地文本猜原因；
- 对手战场目标应明确显示“敌方目标”，避免红框被误读为伤害已经发生。

### 8.4 指向型随从效果

指向型随从效果至少分为：

1. **战吼选择**：随从成功上场后，再开启指向会话；上场位置不是效果目标。
2. **Spellcraft**：生成临时法术后由手牌法术流程处理；生成者只作为来源追踪字段。
3. **磁力/附着**：目标是己方战场机械等可附着对象；需要 `CanReceive` 过滤器。
4. **选择酒馆随从**：来源是随从效果，目标域是 `TavernShop`；不能套用己方战场候选。
5. **自动触发增益**：若文本是“随机一个/每个/所有”，不进入玩家指向态。

视觉上，来源框应落在真正触发效果的随从或临时效果卡上；结算完成后可短暂保留来源→目标关系，但不把自动触发伪装成玩家拖拽。

### 8.5 双目标与多目标

统一要求：

- `requiredCount` 必须由卡牌规则声明；
- `allowDuplicate` 默认 false；
- `selectionOrder` 明确是有序还是无序；
- 每次确认后立即更新 `selectedTargets[]`，不能只保存在 UI；
- 目标失效时按规则回退：若已选目标仍合法，保留；若目标本身消失，提示并重新选择该步骤；
- 完成前不能触发半成品结算；
- 目标顺序影响效果时，事件日志和回放必须保留顺序。

## 9. 输入设备规范

### 9.1 鼠标

- 左键拖拽和点击激活两种方式都支持；
- 目标卡悬停 0–90ms 内进入预览，不使用长 tooltip 延迟阻塞操作；
- 释放在非法目标上不结算，保留来源态并显示原因；
- 右键/Esc 取消；
- 目标连线跟随目标卡中心/边缘，而不是鼠标光标，减少线条抖动。

### 9.2 键盘/手柄

- 先聚焦来源，再按确认进入 `Armed`；
- D-pad/左摇杆只在合法候选集合中导航，非法对象不应成为焦点死路；
- 焦点指示不能只换颜色，要有高对比外框/角标；
- A/Cross 确认，B/Circle 取消；
- 多目标时 LB/RB 或肩键可切换目标区域，避免手柄需要精确指向屏幕坐标；
- 顶部提示显示当前步骤和可用操作，例如 `选择第 2 个目标 · A 确认 · B 返回`；
- 输入图标必须来自当前绑定，不得硬编码 `[A]`、`[B]`。

### 9.3 触摸

- 可视卡面可以小，但可触区域至少 44×44pt/48×48dp 等效尺寸；
- 长按或拖拽进入指向，滑出有效区域再松手视为取消/无效释放；
- 不用细线作为唯一命中区域；目标卡整块区域可触；
- 手指遮挡目标时，目标名和当前步骤显示在顶部/底部安全区；
- 触摸反馈与鼠标反馈共享状态机，不复制一套目标逻辑。

## 10. Unity 实施落点

### 10.1 推荐分层

```text
Card/Power Definition
        ↓ 生成 TargetingRequest
TargetingSessionService（会话、步骤、候选、取消）
        ↓
TargetCandidateResolver（按区域和过滤器查询）
        ↓
GameCommand / MatchService（最终校验与结算）
        ↓
UnityTargetingPresenter（框、标签、箭头、提示、动画）
```

### 10.2 现有文件的最小改造建议

| 文件 | 作用 | 建议 |
|---|---|---|
| `Runtime/Domain/Models/Enums.cs` | 区域枚举 | 先保留兼容值；需要时再增加英雄/扩展域，不在 UI 中硬编码字符串 |
| `Runtime/Application/Commands/GameCommand.cs` | 命令载荷 | 继续复用双目标和实例 ID；新增命令类型前先确认旧命令兼容 |
| `Runtime/Presentation/.../UnityTavernDragController.cs` | 拖拽转命令 | 从 `CanDrop` 猜规则，迁移为调用目标候选/会话查询 |
| `Runtime/Presentation/.../UnityTavernCardComponent.cs` | 卡牌视觉状态 | 保留已有状态，补充目标序号、非法原因和减少动态效果分支 |
| `Runtime/Presentation/.../UnityTavernTrainerController.cs` | 页面编排 | 保留拖拽幽灵/连接器，但把会话和动画时序移入可测试 presenter/session |
| `Runtime/Application/Services/MatchService.cs` | 最终校验/结算 | 统一消费目标实例 ID；所有 UI 结果都要再次验证 |
| `Docs/TargetingClarityDesign.zh-CN.md` | 视觉基线 | 保持来源/目标框与回放规则，链接到本专项 |

### 10.3 不建议的做法

- 不要在每张卡的按钮回调里手写一遍 `IsValidTarget`。
- 不要让装饰箭头、标签、Outline 组件接收 Raycast。
- 不要用卡牌数组索引作为唯一目标身份。
- 不要把 `targeted_spell` 标签当成完整目标规则；它只能表示“进入指向流程”，不能决定目标域和过滤器。
- 不要用一个全局静态动画协程管理多个会话；来源卡切换或取消时容易残留。

## 11. 分阶段实施顺序

### Phase A：契约与回归基线

- 盘点所有带 `targeted_spell`、HeroPower 目标参数、Battlecry target、Spellcraft target 的卡牌/效果。
- 为每个条目补齐 `sourceKind`、允许区域、目标数量、过滤器、是否允许重复。
- 为现有 `UnityTavernTargetingState` 添加单元测试，不改视觉样式。
- 给 `MatchService` 目标解析增加实例 ID 优先的回归测试。

### Phase B：单目标统一会话

- 先迁移英雄技能→己方/敌方战场。
- 再迁移酒馆法术→己方战场和酒馆目标。
- 将拖拽控制器的合法性查询改为目标会话提供的候选集合。
- 保留旧命令载荷，确保行为回归通过。

### Phase C：指向型随从与 Spellcraft

- 战吼目标在上场成功后建立会话。
- Spellcraft 生成卡统一走手牌法术目标流程。
- 磁力/附着效果增加 `CanReceive` 过滤器和专门目标标签。

### Phase D：多目标与跨区域

- 支持 `requiredCount > 1`、已选目标集合、目标顺序和去重。
- 增加 `TavernShop + FriendlyBoard` 等跨区域并集规则。
- 增加手柄区域切换和触摸目标摘要。

### Phase E：回放与结果层统一

- 复用来源/目标视觉语言，但不复用玩家输入态的 Raycast/取消。
- `ActorId/TargetId` 缺失时使用效果来源/受击对象名称回退。
- 自动/随机/全体效果只显示结果关系，不显示“可选目标”。

## 12. 测试矩阵

### 12.1 领域/服务测试

| 测试 | 期望 |
|---|---|
| 目标域匹配 | 只返回声明区域内的目标 |
| 错误类型 | 目标类型/种族/关键字不匹配返回稳定 `reasonKey` |
| 实例优先 | 卡牌重排后按实例 ID 仍解析到同一目标 |
| 索引兼容 | 没有实例 ID 时旧索引路径仍可工作 |
| 多目标 | 数量、去重、顺序和第二目标缺失均有明确结果 |
| 来源失效 | 来源离场/费用不足/阶段切换时会话不能确认 |
| 目标失效 | 目标消失后服务拒绝旧目标，不误作用于同索引新卡 |
| 非指向效果 | random/all/each 不创建玩家 TargetingSession |

### 12.2 UI/EditMode 测试

| 测试 | 期望 |
|---|---|
| Source 状态 | 来源框、来源标签显示；装饰元素不可 Raycast |
| Candidate 状态 | 只有合法候选高亮，不合法目标降亮 |
| Preview 状态 | 目标框、目标名、连线同步出现 |
| Invalid 状态 | 不可确认，原因提示出现一次且不阻塞其他按钮 |
| Confirmed 状态 | 目标序号/红框保留到结算或短暂确认时间结束 |
| Cancel | 所有框、线、标签、幽灵卡、临时 Raycast 清理 |
| 多目标 | 第一个目标保留，第二步提示正确 |
| 分辨率 | 1920×1080、1280×720、994×384 不越出安全区 |
| 减少动态 | 动画缩短/静态化，但状态和可操作性不改变 |

### 12.3 PlayMode 输入测试

至少覆盖：

1. 鼠标拖拽英雄技能到己方目标，确认后结算；
2. 鼠标将酒馆法术释放到酒馆目标，目标非法时释放不结算；
3. 点击普通法术来源，再点击目标；
4. 指向型随从战吼上场后进入目标选择；
5. Spellcraft 生成临时法术后再次选择目标；
6. 双目标效果完成第一目标后取消第二目标；
7. 手柄仅用 D-pad/A/B 完成一次目标选择；
8. 触摸拖拽到合法目标并滑出取消；
9. 目标在悬停后被刷新/移除，确认时服务拒绝且 UI 恢复；
10. 进入战斗回放时不出现可操作候选，也不阻塞输入。

## 13. 调试与验收工具

建议增加一个仅开发模式可见的 Targeting Debug 面板：

- 当前会话 ID、来源卡 ID/实例 ID；
- 当前步骤、已选目标、悬停目标；
- 候选总数、合法/非法数量；
- 每个候选的 `TargetZone`、实例 ID、`reasonKey`；
- 当前动画状态和剩余时间；
- 最近一次服务拒绝原因；
- 一键取消并验证清理完整性。

验收时优先看日志和状态快照，不只依赖截图；截图用于验证视觉层，状态快照用于验证契约一致性。

## 14. 风险与待确认项

### 高风险

- 直接把所有法术从 `PlayMinion` 迁移到新命令，可能影响旧测试和回放兼容；先建立适配层。
- 只用索引传目标，在刷新/重排后可能把效果施放到错误卡；实例 ID 必须优先。
- 把酒馆目标和购买槽位共用高亮，会让玩家误认为正在购买；两者要分开视觉语义。

### 中风险

- 现有 `TargetZone` 没有英雄域；如果实际卡牌需要英雄目标，先增加领域枚举和服务测试，再接 UI。
- 多目标效果可能需要“已选目标仍显示但不可再次选择”的独立状态，不能只复用 `ConfirmedTarget`。
- 长连线和多个箭头在窄屏会遮挡酒馆；需要根据布局上下文降级。

### 待确认

- 现有数据中哪些普通法术/英雄技能还没有 `targeted_spell` 或等价规则标签；需要用卡库扫描补齐。
- `TavernShop` 是否需要细分为“普通酒馆随从槽位”和“酒馆法术槽位”；取决于后续卡牌是否能直接指向酒馆法术。
- 是否需要支持敌方英雄目标、玩家英雄目标；若当前卡池没有，可先保留扩展枚举而不启用 UI。
- 当前回放事件中 `ActorId/TargetId` 的缺失率和目标名称回退策略，需要用实际回放数据验证。

## 15. 最终检查清单

### 规则

- [ ] 每种来源都有明确 `sourceKind`。
- [ ] 每张指向卡都声明允许区域、数量、顺序、去重和过滤器。
- [ ] 随机/全体/自动效果没有进入玩家指向态。
- [ ] 服务层确认时重新验证目标。

### 交互

- [ ] 鼠标、触摸、手柄都有激活、确认和取消路径。
- [ ] 非法目标可解释且不能确认。
- [ ] 多目标显示进度并保留已选目标。
- [ ] 来源消失、目标消失、阶段切换后会话安全清理。

### 动画

- [ ] 来源金框、候选、悬停目标、确认目标语义统一。
- [ ] 连线不拦截 Raycast，不遮挡核心信息。
- [ ] 默认动画短于 300ms，存在减少动态效果分支。
- [ ] 颜色不是唯一语义，至少有边框/标签/图标备份。

### 工程

- [ ] 复用 `GameCommand` 的实例 ID和双目标载荷。
- [ ] 不在卡牌回调里复制目标合法性逻辑。
- [ ] 有领域、服务、UI、PlayMode 四层测试。
- [ ] 1920×1080、1280×720、994×384 均完成截图或自动断言。
