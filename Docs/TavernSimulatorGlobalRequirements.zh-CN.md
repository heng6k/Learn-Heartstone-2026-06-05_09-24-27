# 酒馆模拟器全局产品与质量要求

## 1. 文档目的

本文定义酒馆模拟器所有功能、卡牌、机制和 UI 修改都必须遵守的全局要求。

它不是某一个界面的临时需求，而是后续开发、代码审核、测试和版本验收的共同基线。专题实现文档可以增加更严格的要求，但不能降低本文标准。

## 2. 当前产品范围

- 只实现单人酒馆训练和战斗模拟，不实现双打专属系统。
- 玩家必须能够完成：配置对局、进入酒馆、买卖和打出卡牌、摆位、配置对手、推进回合、查看战斗和回放。
- 调试工具可以保留，但必须和正常玩家操作分层，不能让用户误以为调试命令属于正式酒馆规则。
- 当前优先支持键盘和鼠标。
- 手柄导航属于后续工作，本轮不实施，也不作为本轮验收阻塞项。

## 3. 全局硬性要求

### 3.1 描述翻译和本地化完整性

#### 适用范围

翻译要求覆盖所有玩家可见内容，不只覆盖主界面按钮：

- 普通随从、金色随从、酒馆法术、英雄、英雄技能、伙伴。
- 任务、任务奖励、饰品、畸变、时空酒馆卡牌和其他高级机制。
- 所有卡牌库、筛选器、详情面板、悬停提示和自由选择界面。
- 发现、任务选择、饰品选择、英雄选择、第二英雄技能选择等所有候选项。
- 错误提示、成功反馈、空状态、禁用原因、状态标签、战斗日志和回放事件。

#### 内容要求

- 中文模式下不得直接显示未处理的英文描述、内部枚举名、CardId、调试字段或占位文本。
- 卡牌名称和描述必须表达实际实现效果，不能只翻译官方原文却与模拟器行为不一致。
- 关键词必须使用统一中文名称和统一说明，不能同一关键词出现多种翻译。
- 描述中的数值、回合、目标、临时/永久、战斗内/酒馆内限制必须完整保留。
- 英文模式使用英文内容；语言切换后，当前页面、弹窗、列表和错误信息必须一起刷新。
- 缺少翻译时，开发环境可显示明显的 `[缺少翻译]` 标记并记录日志；对外版本不得静默回退为内部字段。

#### 卡牌库和选择界面要求

每个候选卡至少显示：

- 本地化名称。
- 本地化完整描述或可展开的完整描述。
- 类型、等级、种族、费用等选择所需信息。
- 当前实现状态；未完整实现时必须明确说明。
- 不可选择时的具体原因，不能只变灰。

所有搜索应同时支持：

- 当前语言名称。
- CardId 精确搜索，仅在高级/调试模式提供。
- 关键词和类型搜索。

#### 验收标准

- 对所有卡牌库和选择界面运行本地化覆盖报告，玩家可见文本缺失数为 0。
- 中文模式抽样检查各类型卡牌时，不出现裸英文枚举、内部键和无说明 CardId。
- 语言切换后不需要退出当前流程即可看到新语言。
- 长中文描述可阅读、可滚动或可展开，不因空间不足被截断成无法理解的内容。

### 3.2 时空酒馆开启后的触发安全

时空酒馆开启后必须进入明确、可验证的独立状态，不能依赖零散布尔值让普通酒馆和时空酒馆同时执行不兼容流程。

#### 必须保证

- 同一回合中饰品选择先处理，时空酒馆后处理。
- 存在未完成的强制选择时，不能开始战斗、完整推进下一回合或再次生成同类选择。
- 时空酒馆只能开启一次对应流程，不得因 UI 重建、重复点击、刷新或恢复选择而重复触发。
- 进入、购买和退出时空酒馆不能错误刷新或覆盖普通商店。
- 时空酒馆购买只扣除其规则指定资源，不得重复触发普通商店的扣费或购买逻辑。
- 时空酒馆卡牌只能进入允许的目的地；满手牌、满战场、资源不足时必须保持状态一致并说明原因。
- 退出后必须恢复普通酒馆的商店、冻结、槽位和当前回合状态。
- 保存/加载、重建 UI 或打开其他弹窗不得丢失时空酒馆状态。

#### 禁止触发清单

除非具体卡牌规则明确要求，时空酒馆开启、浏览或普通刷新不得额外触发：

- 普通商店刷新次数和刷新奖励。
- 普通购买、出售、打出或召唤事件。
- 回合开始、回合结束、战斗开始或战斗结束事件。
- 三连结算、任务进度、饰品计数和英雄技能计数。
- 第二个时空酒馆选择或其他高级机制选择覆盖当前选择。

真正完成购买、打出或召唤时，只触发该动作按照正式规则应产生的事件，并且每个事件只触发一次。

#### 验收标准

- 为开启、重复开启、购买成功、购买失败、满手牌、退出、下一回合、保存加载建立黑盒测试。
- 对所有禁止触发项记录触发计数，期望值必须为 0。
- 同一命令重复提交或 UI 重复点击不能重复扣费、重复发牌或重复结算。
- 时空酒馆结束后普通酒馆状态与进入前的快照一致，允许变化的字段必须有明确列表。

### 3.3 UI 排版和信息架构

- 商店、己方战场、手牌和主操作始终是主视觉区域。
- 对手配置、日志、建议、卡牌详情和调试工具作为次级信息，按需展开。
- 未开放功能不得占据主入口的同等视觉层级。
- 每个页面必须有一个明确主操作和稳定的返回路径。
- 禁用按钮必须提供原因；定向操作必须显示当前状态和取消方式。
- 复杂设置采用“快速开始 + 自定义设置”的渐进式结构。
- 所有弹窗必须通过统一 Modal Stack 管理，避免多层 Overlay 同时争抢输入。
- 列表和弹窗在内容超出时必须滚动，不允许依靠压缩字号硬塞。

#### 尺寸与响应式基线

- 设计基准：1920×1080。
- 必测尺寸：1920×1080、1366×768、1280×720、1000×600、994×384。
- 正文建议 16–18，辅助文字不得低于 14，核心信息不得低于 18。
- 主要交互目标建议至少 44×44；重要操作建议至少 48 高。
- 不同分辨率下不得出现关键控件越界、重叠、不可滚动或文本无法理解的截断。

### 3.4 UI 视觉美化和一致性

- 保留酒馆氛围，但不使用大量无法区分层级的相近暗色面板。
- 建立统一 Design Tokens：颜色、字号、间距、圆角、边框、阴影、按钮高度和动画时长。
- 主操作、经济操作、战斗操作、危险操作、工具操作和禁用状态必须可以快速区分。
- 所有可点击控件必须具有 normal、hover、pressed、selected、disabled 状态。
- 颜色不能作为唯一状态编码；同时使用图标、形状、文字或边框变化。
- UI 动画用于说明状态变化，不作为无意义装饰；常规反馈建议在 100–300ms 内完成。
- 卡牌美术、文字和攻血信息之间保持清晰层级，不能互相遮挡。

### 3.5 随从关键词对外显示和状态变化反馈

关键词必须同时解决“现在拥有什么”和“刚刚发生了什么”。

#### 关键词获得

- 获得时播放一次短暂的出现反馈，例如图标弹入、边框闪光或卡牌上方短文字。
- 明确显示关键词名称，例如“获得圣盾”，不能只改变颜色。
- 战斗回放和事件日志记录获得来源、目标和关键词。

#### 关键词保持

- 当前拥有的关键词使用稳定图标、徽标、边框或卡牌效果持续显示。
- 长期状态不能依赖持续闪烁动画。
- 临时关键词应带有临时标记或在详情中说明持续时间。
- 卡牌详情和悬停提示显示关键词的统一中文说明。

#### 关键词消失

- 消失时播放短暂的退出反馈，例如图标破裂、淡出或“失去圣盾”文字。
- 视觉效果结束后，持久标记必须立即与真实状态一致。
- 一次性关键词消耗、临时效果到期、沉默/变形移除等原因应在回放或日志中可区分。

#### 状态一致性

- UI 不自行推测关键词变化，必须消费领域层或应用层输出的状态差异/事件。
- UI 重建、回放跳帧和暂停恢复后，关键词显示必须从当前权威状态恢复。
- 同一关键词重复获得但状态未改变时，不重复播放“获得”动画；需要表达刷新持续时间时使用单独事件。

#### 验收标准

- 嘲讽、圣盾、烈毒/剧毒、复生、风怒、潜行等核心关键词至少各有获得、保持、消失测试。
- 回放上一帧/下一帧时，关键词标记与该帧状态一致。
- 低分辨率下关键词不会遮挡攻血、名称和主要交互。
- 关闭动画或减少动态效果时，仍能通过图标和文字理解状态变化。

## 4. 通用交互要求

- 危险操作需要确认或防重复提交。
- 命令执行成功和失败都必须给出中文反馈。
- 对重复点击、空列表、资源不足、满手牌、满战场和不存在目标进行保护。
- 打开弹窗后聚焦主控件；关闭后恢复到触发控件。手柄方向导航暂缓，但键盘焦点不能完全丢失。
- Toast 不能覆盖关键选择，也不能被无关 UI 重建立即清除。
- 不能通过隐藏错误或静默失败维持流程；失败必须说明原因并保持状态不变。

## 5. 工程和测试要求

- 领域规则、应用命令和 UI 展示保持单一权威来源。
- 普通操作不应销毁并重建整个 UI 树；优先局部刷新相关区域。
- 自动化测试至少包含领域规则、命令边界、View 状态和关键分辨率验收。
- 每个新卡库和选择器必须加入翻译覆盖、空态、筛选、滚动、选择成功和选择失败测试。
- 每个新关键词变化必须加入事件、当前状态和回放一致性测试。
- Console 不得出现项目业务异常；Prefab 引用缺失不能静默降级。
- 测试证据和功能实现状态必须遵循 [TavernPlayerPerspectiveTestingStandard.zh-CN.md](TavernPlayerPerspectiveTestingStandard.zh-CN.md)。白盒通过不能单独作为 `Implemented` 的依据。

## 6. 本轮明确暂缓

以下内容记录在 Backlog，不进入当前优化计划的完成定义：

- 完整手柄方向导航图。
- Xbox、PlayStation、Switch 动态按键图标。
- 控制器重绑定和平台确认/取消键习惯适配。

现有修改不得主动破坏 Unity `Selectable` 基础能力，以免增加未来接入成本。
