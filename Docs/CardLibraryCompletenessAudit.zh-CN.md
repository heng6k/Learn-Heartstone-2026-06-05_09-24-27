# 卡牌库随从显示完整性审计

## 实施状态（2026-07-18）

已完成修复：

- 打开玩家、对手棋盘或对手手牌卡牌库时，恢复随从、全部等级、全部种族、空搜索、当前局的默认状态。
- 切换卡牌类别时同步清空旧等级、种族、搜索及英雄技能分类条件。
- 移除最终结果集的静默 `.Take(80)`。
- 主卡牌库和旧工具卡牌列表均改为每批显示 80 张，并通过“加载更多”继续显示完整结果。
- 标题计数继续使用过滤后的完整结果数量，而不是当前已加载数量。
- 英雄技能和英雄伙伴同样支持加载第 81 项后的内容。
- 未修改自定义卡池、当前局种族过滤和 CardId 规则。

验证结果：

- Unity Roslyn Runtime 与 EditMode Tests 编译通过。
- 新增“重新打开后清除旧筛选、五本布莱恩可见、加载更多后全量可达”测试通过。
- 三项卡牌库专项 UI 回归：3/3 通过。
- MCP 查询在测试运行期间曾因单次超过 30 秒而断开，但 Unity Test Runner 最终结果文件确认 3 项全部通过。

## 结论

布莱恩·铜须的数据、图片、五本等级和当前自定义卡池配置均正常。它在“五本”列表内部位于第 5，不是数据缺失。

当前存在两个独立问题：

1. 卡牌库重新打开或切换等级时不会清除之前的种族和搜索条件，导致用户看到的是组合筛选，却容易误认为只筛选了五本。
2. 卡牌库对所有非英雄类别统一执行 `Take(80)`，导致全量浏览时大量卡牌被静默截断。

## Root Cause Analysis

**Error**：筛选五本后看不到布莱恩·铜须；全量卡牌库也存在大量随从不可见。

**Expected**：从默认状态选择五本时，所有符合当前卡池和当前局种族规则的五本随从都应出现；选择“显示全部”时不应静默丢弃第 81 张后的卡牌。

**Cause**：

- `OpenCardLibrary` 没有重置 `toolsAcquisitionTierFilter`、`toolsAcquisitionTribeFilter` 和 `toolsAcquisitionSearchText`。
- 点击等级按钮只修改等级，旧种族和搜索条件继续生效。
- `FilteredToolsAcquisitionChoices` 在过滤、排序后对非英雄类别统一执行 `.Take(80)`。

**Fix**：

- 打开卡牌库时恢复明确的默认筛选，或增加明显的“重置筛选”入口和当前条件提示。
- 移除静默 `Take(80)`，改为分页或“加载更多”；搜索和筛选应作用于完整数据集。
- 对随从、英雄技能和伙伴分别增加“最终可见数量等于符合条件数量”的测试。

**Prevention**：测试不能只验证某张卡能够通过额外的“中立”筛选找到，还要覆盖从新打开卡牌库直接选择五本、关闭后带旧筛选重新打开，以及总数超过页面容量的场景。

## 预期过滤与错误遗漏的区别

以下属于预期过滤：

- “当前局”隐藏未激活种族随从。
- 自定义卡池版本隐藏未启用卡牌。
- 选择具体种族时，中立随从只在“全部”或“中立”中出现。
- 搜索词、等级和种族可以组合使用。

以下属于需要修复的问题：

- 重新打开卡牌库仍保留旧筛选，却没有足够明显地提示用户。
- “显示全部”仍只展示前 80 张。
- 英雄技能和伙伴同样被 80 张上限截断。
- 计数文本显示的是截断后的数量，用户无法知道还有卡牌未加载。

## 推荐修复顺序

1. 打开玩家/对手卡牌库时重置等级、种族和搜索条件，确保默认入口可预测。
2. 增加“清除全部筛选”按钮，并在标题处明确显示当前组合条件。
3. 将 `.Take(80)` 改为分页或“加载更多”，不建议一次创建 248 张复杂 Unity 卡牌对象。
4. 搜索必须针对完整集合，分页只处理搜索后的结果。
5. 补充布莱恩、最后一张五本、最后一张六本、英雄技能第 81 项和伙伴第 81 项测试。
