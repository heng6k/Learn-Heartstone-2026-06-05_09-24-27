# 任意卡牌获取与自定义对手 UI 设计

日期：2026-06-06

## 背景

当前 Unity 版酒馆训练器已经具备招募阶段基础操作、代表性随从效果切片、基础战斗模拟和右侧检查器区域。下一阶段在继续扩展战斗事件队列前，需要一个更快的测试入口：玩家可以直接拿到任意随从或酒馆法术，对手战场也可以快速搭建和编辑。这样后续验证亡语、复生、圣盾、嘲讽、剧毒、召唤衍生物、复仇计数等战斗机制时，不再依赖随机商店刷新。

本设计只定义 UI 和应用层能力，不实现战斗事件队列本身。

## 目标

- 在训练器右侧区域增加标签页切换。
- 第一个新能力是“获取卡牌”：搜索任意随从或酒馆法术，并加入玩家手牌。
- 第二个新能力是“自定义对手”：在独立右侧标签页中编辑对手战场。
- 对手随从支持添加、删除、调整站位、修改攻击/生命/最大生命、切换关键词。
- 保持规则层仍由 `MatchService` 和领域模型负责，UI 不直接绕过应用层修改复杂状态。
- 第一版优先服务测试效率，不做完整场景库、复杂筛选器或视觉重做。

## 非目标

- 不把任意卡牌直接放入玩家战场、酒馆或对手战场的通用获取面板。
- 不做完整 279 张卡的真实效果补全。
- 不做战斗事件队列、完整亡语队列、复仇计数或战斗开始事件。
- 不做远程顾问、AI 自动构筑、场景分享。
- 不重做整套 TavernTrainer 视觉风格。

## UI 结构

`TavernTrainerView` 当前右侧是一个垂直检查器区域，包含对手战场、随从编辑、提示和日志。新设计把右侧改成带标签页的检查器：

```text
RightInspector
  Tabs
    - 对局信息
    - 获取卡牌
    - 自定义对手
  Active Tab Content
```

### 对局信息标签

保留当前右侧默认信息：

- 对手战场紧凑预览。
- 选中随从编辑器。
- 本地建议。
- 招募/战斗日志。

这个标签用于保持现有工作流不丢失。默认打开该标签。

### 获取卡牌标签

用于快速把牌加入玩家手牌。

控件：

- 搜索输入框：匹配名称、卡牌 ID、文本。
- 类型切换：全部 / 随从 / 酒馆法术。
- 简单筛选：酒馆等级、种族、关键词。
- 搜索结果列表：显示名称、等级、种族/类型、身材或费用。
- 主要按钮：加入手牌。

行为：

- 点击“加入手牌”后，应用层创建对应 `MinionInstance` 并加入 `State.Player.Tavern.Hand`。
- 如果手牌已满，返回明确错误并显示在 UI 顶部或当前标签内。
- 酒馆法术作为 `CardKind.TavernSpell` 加入手牌，沿用现有 `PlayMinion` 中的酒馆法术施放路径。
- 加入手牌的卡不占用随从池副本，`PoolSource` 应标记为调试/生成来源，避免污染酒馆池回收逻辑。

### 自定义对手标签

用于搭建战斗测试靶场。

控件：

- 对手战场 7 个槽位。
- 搜索并添加随从区域。
- 选中对手随从的编辑区。
- 站位按钮：左移、右移、删除。
- 身材输入：攻击、生命、最大生命。
- 关键词切换：嘲讽、圣盾、剧毒、烈毒、风怒、潜行、复生、亡语、磁力等当前枚举中已有关键词。

行为：

- 添加随从时进入 `State.Opponent.Board`。
- 对手战场满 7 个时禁止添加并显示错误。
- 调整站位只影响对手战场列表顺序。
- 修改身材时保持基本约束：攻击不小于 0，最大生命不小于 1，当前生命在 1 到最大生命之间。
- 关键词切换写入目标随从实例的 `Keywords`。
- 这些编辑只影响当前练习局，不回写原始 JSON。

## 应用层设计

建议扩展 `GameCommandType`，让 UI 通过命令修改状态：

- `AddCardToHand`
- `AddOpponentMinion`
- `RemoveOpponentMinion`
- `MoveOpponentMinion`
- `UpdateOpponentMinion`

`MatchService` 新增对应处理方法。

### AddCardToHand

输入：

- `cardId` 或 `definitionId`
- `CardKind`

输出：

- 玩家手牌新增一张卡。
- 写入招募日志，例如 `调试获取 <name>`。

规则：

- 手牌上限仍为 10。
- 随从从 `MinionCatalog` 创建实例。
- 酒馆法术从 `SpellCatalog` 创建实例。
- 调试获取来源不减少随从池数量。

### AddOpponentMinion

输入：

- `cardId` 或 `definitionId`

输出：

- 对手战场新增一个随从实例。

规则：

- 对手战场上限为 7。
- 默认使用卡牌基础身材和关键词。
- `Owner = BoardSide.Opponent`。
- `PoolSource` 标记为调试/生成来源。

### UpdateOpponentMinion

复用或扩展现有 `MinionPatch`。

支持字段：

- `Attack`
- `Health`
- `MaxHealth`
- `Keywords`

如果现有 `UpdateMinion` 只覆盖玩家侧或选中随从，需要拆出明确的对手更新路径，避免 UI 根据实例 ID 去猜状态位置。

## 数据流

```text
RightInspector Tab UI
  -> GameCommand
  -> MatchService
  -> MinionCatalog / SpellCatalog
  -> MatchState
  -> TavernTrainerView Rebuild
```

UI 只负责收集输入和展示错误。创建实例、限制手牌/战场上限、日志记录和状态更新都由 `MatchService` 完成。

## 错误处理

第一版使用现有 `lastError` 机制即可。

需要覆盖的错误：

- 搜索结果为空。
- 手牌已满。
- 对手战场已满。
- 找不到目标卡牌定义。
- 更新的实例不存在。
- 输入身材非法。

错误文案显示在当前右侧标签页顶部，避免用户不知道操作失败。

## 测试策略

EditMode 测试优先覆盖应用层，UI 测试只验证关键按钮/标签能构建。

建议新增或扩展：

- `MatchServiceDebugCardTests`
  - 添加普通随从到玩家手牌。
  - 添加酒馆法术到玩家手牌。
  - 手牌满时添加失败。
  - 调试获取不减少随从池数量。
- `OpponentCustomizationTests`
  - 添加随从到对手战场。
  - 对手战场满时添加失败。
  - 删除对手随从。
  - 左右移动对手随从。
  - 修改对手随从攻击、生命、最大生命。
  - 切换对手随从关键词。
- `TavernTrainerViewTests`
  - 右侧标签页构建成功。
  - 获取卡牌标签存在搜索/加入手牌入口。
  - 自定义对手标签存在添加、编辑、移动、删除入口。

完整 Unity EditMode 测试仍通过 `CodexEditModeTestRunner.Run` 执行。

## 实施顺序

1. 为应用层命令写失败测试。
2. 扩展 `GameCommand` 和 `MatchService`，实现玩家手牌调试获取。
3. 写并实现对手添加、删除、移动、更新命令。
4. 把右侧检查器改为标签页结构，保留现有“对局信息”内容。
5. 添加“获取卡牌”标签页的搜索结果和加入手牌按钮。
6. 添加“自定义对手”标签页的战场槽位、搜索添加、身材编辑、关键词切换。
7. 补 UI 构建测试和完整 EditMode 测试。

## 后续扩展

完成第一版后，可以继续做：

- 保存/加载测试场景。
- 常用战斗测试模板，例如“亡语召唤测试”“复生测试”“圣盾剧毒测试”。
- 将调试获取入口升级为正式“场景编辑器”。
- 接入战斗事件队列后，在自定义对手界面直接运行指定测试并查看回放。
