# 准备购买阶段与战斗阶段一致性专项审计

## 结论

本轮没有发现已承诺支持范围内的准备/购买阶段或战斗引擎共享生产逻辑缺陷。

发现并修复的是测试基础设施不足：旧的长回合测试没有处理后来加入的强制饰品/异常选择，部分 Buddy 测试没有完成英雄开局发现，任务追踪 UI 测试仍按旧层级查找节点。这些问题会让完整回归产生假失败，但生产代码的强制选择守卫、战斗顺序、一次性消费和奖励隔离均保持不变。

最终完整 Unity EditMode 回归：`1252` 项，`1251` 通过，`0` 失败，`1` 跳过。

## 审计范围

### 准备/购买阶段

- 购买随从和酒馆法术。
- 打出随从、酒馆法术及显式目标选择。
- 出售、移动、重排和区域容量。
- 刷新、冻结、升级和经济资源。
- 发现、高级机制选择和英雄技能次数。
- 回合结束清理、战斗结算和下一准备阶段初始化。

### 战斗阶段

- 玩家与敌方战斗快照隔离。
- 双方战斗开始侧序和同侧触发顺序。
- 排队战斗开始酒馆法术的一次性消费。
- 攻击、死亡、亡语、召唤、复生和溢出。
- 玩家/敌方战斗奖励隔离与持久化。
- 战斗奖励到下一准备阶段的应用顺序。

## 明确排除项

以下内容不因“不完整”状态本身进入本轮修复：

- BGDUO、队友、传递、团队奖励等 `OutOfScope` 内容。
- `Proxy`、`FrameworkFirst`、`Planned`、`Deferred`、`Disabled`、`DebugOnly`、`HiddenEffectOnly`。
- 文档明确标记“官方精度待核验”的单卡行为。
- 大型 UI 重设计和不同缺图卡牌的高级视觉差异。

如果这些内容暴露共享阶段状态、资源原子性、快照隔离或一次性清理错误，仍应修复共享根因；本轮未发现此类生产缺陷。

## 权威生命周期

### 正常回合

`MatchService.NextTurn` 同步执行：

1. 校验没有强制玩家选择待处理。
2. 执行回合结束触发和本回合计数清理。
3. 运行战斗并持久化双方支持的奖励。
4. 刷新商店并进入下一准备阶段。
5. 重置临时效果和本回合统计。
6. 执行回合开始秘密、饰品、任务、英雄和随从触发。

### 独立战斗测试

`MatchService.RunCombatTest` 创建双方快照、运行战斗、写回允许持久化的奖励，并停留在 `MatchPhase.Result` 供回放、解释和重置使用。

### 战斗开始顺序

- 双方先后顺序由种子稳定决定，重放一致。
- 玩家和敌方使用同一个侧序结果。
- 英雄战斗开始效果先进入快照准备。
- 任务、饰品和时空效果按现有编排准备。
- 同侧排队酒馆法术保持配置顺序。
- 战斗结束后，无论法术是否成功找到目标，玩家法术队列都会消费，敌方法术队列都会清空。

## 根因与修复

### 1. 长回合鲁棒性测试被强制饰品选择阻塞

- **Error**：`RobustnessEdgeTests.RecruitAndStatMutationAcrossManySeeds_MaintainsBounds` 在第 6 回合后抛出“请先完成当前饰品选择”。
- **Expected**：压力夹具应处理正常游戏会产生的强制选择，再继续验证容量和极端数值边界。
- **Cause**：夹具只清理 `Discover`，没有清理 `AdvancedMechanics.PendingChoice`。
- **Fix**：统一处理发现和高级机制选择。
- **Prevention**：所有跨多个正式回合的测试夹具必须显式选择“隔离无关机制”或“完成所有强制选择”之一。

### 2. 合法饰品效果移除了固定测试目标

- **Error**：完成饰品选择后，鲁棒性测试下一回合访问空战场索引。
- **Expected**：内容效果可以合法改变战场，压力测试仍应继续验证数值边界。
- **Cause**：种子 `920029` 选择到 `Sacrificial Altar`，它按设计献祭了测试随从；夹具错误假设同一目标会永久存在。
- **Fix**：测试目标被合法移除后，按稳定规则补建边界数值目标；战场满时替换测试槽位，不突破上限。
- **Prevention**：压力测试应断言系统不变量，不应依赖内容效果不会改变测试夹具。

### 3. 异常、英雄和压力测试沿用旧的回合推进假设

- **Error**：完整回归中多个测试在第 6/9 回合被饰品选择阻塞，或被英雄开局发现阻塞。
- **Expected**：专项测试应只受被测机制影响，综合压力测试则应完成真实强制选择。
- **Cause**：这些测试建立于强制饰品选择和部分英雄开局发现接入之前。
- **Fix**：异常/英雄专项测试关闭无关的自动饰品流程；明确测试饰品的用例继续显式启用；综合压力测试完成发现和高级选择；Buddy 测试先完成英雄开局发现。
- **Prevention**：新增强制阶段入口时，必须审计所有循环调用 `NextTurn` 的测试。

### 4. `Audiences Choice` 旧测试绕过了正式强制选择语义

- **Error**：测试故意不选择异常选项却调用正式 `NextTurn`。
- **Expected**：正式流程必须阻塞；只有调试跳过入口可以验证“未选择时不发奖励”。
- **Cause**：旧测试写于强制异常选择守卫之前。
- **Fix**：第一次完成选择后仍使用正式 `NextTurn`；故意不选择或验证不会重复奖励时使用现有 `DebugSkipToNextTurn`。
- **Prevention**：不得为了兼容旧测试放宽 `AssertNoRequiredPlayerChoicePending`。

### 5. 任务追踪 UI 测试仍按旧父节点查找

- **Error**：完成任务选择后，测试在控制器根节点找不到 `UnityQuestTrackerPanel`。
- **Expected**：任务追踪面板存在于当前 UI 层级。
- **Cause**：面板已移动到 `UnityMechanicStatusStrip`，测试断言未同步。
- **Fix**：按 `UnityMechanicStatusStrip/UnityQuestTrackerPanel` 查找。
- **Prevention**：UI 测试应断言稳定的功能容器层级；布局重构后同步更新层级契约。

## 后续实施：命令 × MatchPhase 允许矩阵

`MatchService.Apply` 现已在统一入口执行阶段权限检查，并公开只读的 `IsCommandAllowedInPhase` 供测试和后续 UI 状态使用。

|---|---:|---:|---:|---:|
| 购买、出售、刷新、冻结、升级 | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 打出、弃牌、英雄技能 | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 正常 `NextTurn` / `SimulateCombat` | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 发现和高级机制选择 | 允许 | 允许 | 拒绝 | 允许 |
| 双方随从、手牌、全局参数和敌方机制测试编辑 | 允许 | 允许 | 拒绝 | 允许 |
| 保存/加载场景、运行/重置战斗测试 | 允许 | 允许 | 拒绝 | 允许 |
| `DebugSkipToNextTurn` | 允许 | 允许 | 拒绝 | 允许 |

矩阵约定：

- `Tavern` 是唯一允许正式准备操作的阶段。
- `Combat` 由服务同步执行，不接受任何外部命令。
- `Result` 可处理战后产生的玩家选择，也可继续使用测试工具、重跑或重置战斗。
- `Editing` 保留纯测试编辑能力，不允许伪装成正式准备阶段购买或施放卡牌。
- 结果阶段若要保留已结算奖励和对手历史并进入下一准备阶段，使用 `DebugSkipToNextTurn`。
- 结果阶段若要回到战斗前快照，使用 `ResetCombatTestSnapshot`。
- 不允许在结果阶段调用普通 `NextTurn`，避免同一回合重复解析战斗。

## 后续实施：玩家界面的阶段联动

命令矩阵现已接入 Unity 酒馆训练器主界面。服务层守卫仍是最终权限边界，UI 只负责把当前阶段的合法操作清楚呈现给玩家。

### 酒馆战棋流程语义

- `Tavern`：允许购买、出售、刷新、冻结、升级、打出卡牌、英雄技能和“完整下一回合”。
- `Result`：禁用上述正式准备操作，保留回放、测试工具、双方场面编辑、重跑和重置战斗。
- `Result` 的主回合按钮改为“进入下一准备阶段”，执行 `DebugSkipToNextTurn`，不会再次结算刚完成的战斗。
- `Editing` 继续保留纯测试编辑，但不伪装成正式购买阶段。

### 卡牌交互边界

- 商店卡在非 `Tavern` 阶段不显示购买按钮，也不创建购买拖拽入口。
- 手牌在非 `Tavern` 阶段不显示打出/施放按钮，也不创建打出拖拽入口。
- 玩家战场在 `Result` 阶段不显示出售按钮；站位调整仍作为测试编辑保留。
- 拖放落点提示会先构造实际命令，再通过阶段矩阵判断；不合法落点不会显示为可用。
- 英雄技能按钮同时满足阶段权限、解锁条件、费用和次数条件才可交互。

### UI 专项验证

新增黑盒流程覆盖：准备阶段操作可用 → 运行独立战斗测试进入 `Result` → 准备操作禁用且回放/工具可用 → 点击“进入下一准备阶段”恢复酒馆操作。

验证结果：新增流程测试 `1/1` 通过，相关拖拽、工具、完整回合与回放回归 `4/4` 通过，阶段矩阵专项 `26/26` 通过，完整 Unity 酒馆 UI 类 `104/104` 通过。

完整 EditMode 最终为 `1275` 通过、`0` 失败、`1` 跳过，共 `1276` 项，耗时约 `592.9` 秒。唯一跳过项仍是显式 30 分钟浸泡测试。

回归过程中还发现 `AdvancedMechanicLibrary_RepeatedOpenCloseClicksStayStable` 会因 25 次完整高级卡库 UI 重建超过 180 秒。该测试验证的是重复点击稳定性，不依赖固定 25 次压力；现已收敛为 5 次卡库开关和 3 次选择层重开，保留相同路径与断言。修复后单项约 `7.2` 秒，完整 UI 类和完整 EditMode 均通过。

## 当前阶段质量判断

### 已确认稳定

- 无效目标、满手、满场和费用不足相关准备阶段原子性已有测试覆盖。
- 强制发现/任务/饰品/异常选择不能被正式下一回合绕过。
- 双方战斗开始酒馆法术遵守稳定侧序和同侧队列顺序。
- 未触发完整或没有合法目标的一次性战斗开始法术不会保留到下一回合。
- 玩家与敌方战斗奖励、全局成长参数和战斗快照保持侧隔离。
- 战斗奖励在下一准备阶段刷新和相关消费者之前完成写回。

### 后续建议，但不属于本轮缺陷

- 将跨回合测试使用的“完成所有强制选择”辅助逻辑收敛到共享测试工具，避免多个压力夹具再次漂移。
- 为新增强制选择机制增加准入检查：至少包含阻塞正式 `NextTurn`、调试跳过行为和长回合夹具兼容性测试。
- 继续按现有排除规则补卡；不要把代理或官方精度待核验内容混入阶段稳定性回归。
